## 3. Naming convention I am using

`<BATCH>_<TYPE>_<ASSET>[_<VERSION>].<ext>` — for example

- `B2_CAND_VR-008_SEALED_QUARTER_V006_2560x1440.png`
- `B2_COMPARE_VR-008.jpg`
- `B2_RETOUCH_GUIDE_VR-007_BLOCKED.jpg`
- `B2_CANDIDATE_REGISTER.md`, `B2_STAGING_LEDGER.md`, `B2_SUBMISSION_MANIFEST.md`

Assets that are **not** finished candidates carry a suffix that says so — `_BLOCKED` for a retouch guide, `_IN_PROGRESS`. Nothing in either folder should ever be readable as approved. This convention is mine, not a requirement of yours.

## 5. Verification bar — a successful upload command is not proof

What I now do for every batch, and what I would suggest you expect of yourself:

1. list the destination folder afterwards and confirm every file is present with the expected name, byte size and parent;
2. compare the Drive-reported `md5Checksum` against the local MD5 for every file;
3. download at least the image candidates back out of Drive and re-hash locally, proving the stored bytes are the bytes submitted;
4. record the result, including any file that failed.
